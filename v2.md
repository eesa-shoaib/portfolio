## Feature 1: Project Detail Pages

**Route:** `/projects/[slug]`

### Data Structure

Add to `src/app/lib/content.ts`:

```ts
export type ProjectSection = {
  heading: string;
  content: string[];
  items?: string[];
};

export type ProjectDetail = {
  slug: string;
  name: string;
  tagline: string;
  overview: string;
  tech: string[];
  secondaryTech?: string[];
  github?: string;
  liveUrl?: string;
  liveLabel?: string;
  heroImage?: string;
  bullets: string[];
  sections: ProjectSection[];
  reviews?: Review[];
};
```

### Sections Per Project

1. **Overview** — 1-2 paragraph summary
2. **System Design** — architecture, data flow, component diagram (text-based)
3. **Tech Stack Deep Dive** — why each technology was chosen, how they connect
4. **Challenges** — problems faced and how they were solved
5. **Results** — outcomes, metrics, lessons learned

### New Files

| File | Purpose |
|------|---------|
| `src/app/projects/[slug]/page.tsx` | Detail page (server component) |
| `src/app/projects/[slug]/loading.tsx` | Skeleton loading |
| `src/app/components/ProjectHero.tsx` | Hero section with name, tagline, tech, links |
| `src/app/components/ProjectSection.tsx` | Reusable content section component |
| `src/app/components/ProjectNav.tsx` | Back link + prev/next navigation |

### Changes to Existing Files

| File | Change |
|------|--------|
| `src/app/projects/page.tsx` | Wrap each `ProjectCard` in `<Link href={/projects/${slug}}>` |
| `src/app/lib/content.ts` | Add `slug` to `projects` array, add `projectDetails` map + `getProjectBySlug()` helper |

### Packages

None — uses existing stack.

## Feature 2: Blog Page

**Route:** `/blog`

### Approach

MDX files as page files in `src/app/blog/*.mdx`. Frontmatter for metadata. Blog index reads all posts via `fs.readdirSync` at build time.

### MDX Frontmatter

```yaml
---
title: "Building Quirk: A RAG Pipeline in Go"
date: "2026-08-15"
summary: "How I built an AI-powered knowledge search system using Go, ChromaDB, and Cloudflare Workers AI."
tags: ["Go", "RAG", "PostgreSQL", "Docker"]
slug: "building-quirk-rag-pipeline-go"
status: "published"
---
```

### New Files

| File | Purpose |
|------|---------|
| `src/app/blog/page.tsx` | Blog index (server component) |
| `src/app/blog/layout.tsx` | Shared MDX styling + component overrides |
| `src/app/blog/*.mdx` | Individual blog posts |
| `src/app/components/BlogCard.tsx` | Card for blog list |
| `src/app/components/MdxComponents.tsx` | Styled MDX elements (headings, code blocks, etc.) |
| `src/lib/blog.ts` | Frontmatter reading helpers (`getAllPosts`, `getPostBySlug`) |

### Packages

| Package | Purpose |
|---------|---------|
| `@next/mdx` | Next.js MDX integration |
| `@mdx-js/loader` | Webpack loader for .mdx files |
| `@mdx-js/react` | Custom MDX component overrides |
| `gray-matter` | Parse YAML frontmatter |
| `reading-time` | Estimated reading time |
| `shiki` | Syntax highlighting (build-time, terminal aesthetic) |

### MDX Component Styling

| Element | Style |
|---------|-------|
| `h1` | `font-mono text-3xl font-black uppercase` |

### Navbar

Add `{ label: "Blog", href: "/blog" }` to the `links` array.

## Feature 3: Project Reviews

**Location:** Bottom of each project detail page (`/projects/[slug]`)

### Phase 1: Static Reviews (Immediate)

Reviews hardcoded in `content.ts`. Zero packages. Full control.

**Data structure:**

```ts
export type Review = {
  author: string;
  role: string;
  text: string;
  date?: string;
};
```

**Added to `ProjectDetail`:**

```ts
reviews?: Review[];
```

**New files:**

| File | Purpose |
|------|---------|
| `src/app/components/ReviewCard.tsx` | Single review display |
| `src/app/components/ReviewSection.tsx` | Reviews grid container |

**ReviewCard layout:**

```
┌─────────────────────────────────────┐
│  [Initials Circle]                  │
│  Author Name                        │
│  Role, Company                      │
│  ─────────────────────────────────  │
│  > "Review text here..."            │
│                          2025-08    │
└─────────────────────────────────────┘
```

- Initials-based avatar (no images needed)
- Background color derived from author name hash
- Terminal-style quote with `>` prefix
- `BezelPanel` wrapper with `bg-base-200`

**ReviewSection:**
- `BracketChip` "Reviews" + heading "What others say"
- Grid: `grid gap-5 md:grid-cols-2`
- Renders nothing if no reviews

### Phase 2: Dynamic Reviews (Future Upgrade)

Supabase-backed with submission form and moderation.

**Supabase schema:**

```sql
create table reviews (
  id uuid default gen_random_uuid() primary key,
  project_slug text not null,
  author text not null,
  role text not null,
  text text not null,
  approved boolean default false,
  created_at timestamp with time zone default now()
);

alter table reviews enable row level security;

create policy "Public read approved reviews"
  on reviews for select using (approved = true);

create policy "Anyone can submit reviews"
  on reviews for insert with check (true);
```

**Additional packages:**

| Package | Purpose |
|---------|---------|
| `@supabase/supabase-js` | Supabase client |
| `@supabase/ssr` | Server-side Supabase for Next.js |

**Additional files:**

| File | Purpose |
|------|---------|
| `src/app/components/ReviewForm.tsx` | Client component: submission form |
| `src/app/actions/reviews.ts` | Server Action for review submission |
| `src/lib/supabase.ts` | Supabase client singleton |
| `src/lib/reviews.ts` | CRUD functions |

**Moderation:** Toggle `approved` in Supabase dashboard.
